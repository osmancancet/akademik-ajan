# References written by language models: run A (agent context)

_Generated by `eval/llm/report.py` from `numbers.json`. Do not edit numbers by hand._

## Setup

Three models (claude-haiku-5-5, claude-opus-5-5, claude-sonnet-5-5) each answered 12 closed-book requests for 10 references (6 international topics prompted in English, 6 Turkish-literature topics prompted in Turkish), with no tool use. The models ran as Claude Code sub-agents whose context held a user profile and a project rule against bibliographic data from memory; see [ADR-0003](../../docs/adr/0003-llm-reference-study.md). Results describe that agent context, not the models in isolation.

Ground truth: blind web adjudication of 72 references, namely all 42 that verifier v0.1.0 did not mark `verified` and a random 30 of its 142 verified ones. Adjudicators saw only the citation text.

## 1. Did the model produce a list?

| Model | English topics | Turkish topics |
|---|---|---|
| haiku | complied 6 | abstained 5, partial 1 |
| sonnet | complied 6 | abstained 4, no_json 2 |
| opus | complied 6 | abstained 1, no_json 4, partial 1 |

All 18 of 18 English requests returned a full list. Of 18 Turkish requests, 0 returned a full list and 2 a partial one; the rest declined, citing uncertainty and, in many replies, the project rule. Only 3 Turkish-topic references were produced, so the analysis below concerns the English topics.

## 2. How accurate were the references?

Adjudicators found **0 non-existent works** and **4 references with wrong details** among 184 references. Every sampled verified reference was correct (30/30; 95% CI for the error rate among verified references: 0.0–11.3%).

| Model | References | With wrong details | Rate (95% CI) |
|---|---|---|---|
| haiku | 62 | 4 | 6.5% (2.5–15.4%) |
| sonnet | 60 | 0 | 0.0% (0.0–6.0%) |
| opus | 62 | 0 | 0.0% (0.0–5.8%) |

Wrong fields: doi 3, title 1, venue 1. The typical error is a real paper with a DOI that resolves to a different paper; a reader who clicks the DOI lands on the wrong work.

## 3. How well did the verifier separate them?

Strict: only `verified` passes. Lenient: `partial_match` (e.g. year off by one) also passes.

| Verifier | Rule | Errors caught | False alarms on correct references (95% CI) |
|---|---|---|---|
| v0.1.0 (blind) | strict | 4/4 | 38/180 = 21.1% (15.8–27.6%) |
| v0.1.0 (blind) | lenient | 3/4 | 25/180 = 13.9% (9.6–19.7%) |
| v0.2.0 (tuned on this sample) | strict | 4/4 | 33/180 = 18.3% (13.4–24.6%) |
| v0.2.0 (tuned on this sample) | lenient | 3/4 | 24/180 = 13.3% (9.1–19.1%) |

Under the strict rule v0.1.0 flagged every erroneous reference, and 3 of its 4 `mismatch` verdicts were real errors. The cost is false alarms: 38 correct references were flagged, 24 of them cited without a DOI and 17 checked while OpenAlex was unavailable (keyless daily quota). After the v0.2.0 fixes, 30 of the 33 remaining false alarms are conference papers (NeurIPS, ICLR, USENIX Security and similar), which Crossref largely does not index. The v0.2.0 fix for online-first versus print years removed the one false `mismatch`; v0.2.0 figures are optimistic because the fix came from this sample.

## Limitations

- Agent context, not isolated models: the project rule and user profile were visible.
- One sample per model and topic; temperature not controlled.
- 4 errors is a small count; per-model rates have wide intervals.
- Adjudication was done by language-model agents with web access, not by people. The 4 error labels were re-checked against the Crossref record of the cited DOI (4 confirmed); the `correct` labels were not re-checked by a person.
